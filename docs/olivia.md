Olivia on Etapel uses the VPS Olivia 3.5 engine, with a dedicated `etapel` tenant and service account. The shared site layout loads the Spanish/English floating chat on every page.

Browser → `/api/olivia` (Vercel function) → authenticated `/etapel/chat` gateway on `https://olivia.o7digitalgroup.com` → private Olivia `/v1/chat`.

Vercel stores `OLIVIA_GATEWAY_KEY` as a server-only environment variable. The gateway runs from `/opt/o7/apps/etapel-olivia` on `o7-vps`, using `infrastructure/olivia/compose.yaml`. Its private `.env` contains `GATEWAY_KEY`, `OLIVIA_EMAIL` and `OLIVIA_PASSWORD`; never commit this file. No V3 JWT, password or gateway key is exposed to the browser. The VPS ingress has one exact `/etapel/chat` route to this gateway; the core V3 API remains private.

The website proxy fixes routing to `POWERFUL` server-side; visitor-supplied routing is ignored. The gateway accepts only authenticated `FAST` or `POWERFUL` requests and defaults to `FAST` for older site proxies that omit the field. This keeps existing deployments compatible while the updated proxy is reviewed on `dev`. The gateway fixes the tenant, limits messages per visitor IP, signs conversation identifiers, and sends the approved site facts in `knowledge.txt` with every request. Conversations remain in the V3 tenant database. Browser state lasts for the current page; no contact details are required. The privacy link and advisor contact are available inside the panel. Tool integrations remain in the engine's sandbox. Explicit information, quote and callback requests reveal an inline contact form, also accessible through the advisor button. It collects first name, last name, email, phone and preferred contact method (email, phone or WhatsApp), with required privacy consent. Visitor submissions use the existing Etapel Formspree endpoint, `https://formspree.io/f/xeewlkng`, independently of the AI engine. The request includes page, language and recent chat context; success is shown only after Formspree accepts it. Failed submissions retain the entered fields for retry.

Deploy the backward-compatible gateway before deploying the updated site proxy. The widget markup, styling, animations and contact form do not need to change for this engine-mode upgrade.

Update `knowledge.txt` when approved business content changes, then copy the gateway files to the VPS and run `docker compose up -d --force-recreate` there. Validate `docker exec etapel-olivia-gateway node -e 'fetch("http://localhost:3096/health").then(r=>r.text()).then(console.log)'`. To roll back the mode upgrade, redeploy the previous site proxy: requests without routing continue to use `FAST`. Restore an earlier gateway backup only after rolling back the site proxy; other Olivia tenants are independent of this gateway.
